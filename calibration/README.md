# 光路自动标定与相位训练

这里保存真实光路的标定训练与相机反馈流程。棋盘格只作 GUI demo 示例，不作为自动标定相位图。

完整的设计依据、坐标约定、判断条件与后续扩展见 [PLAN.md](PLAN.md)。

## 当前实现

- 普通显示器输出 DMD、SLM1、SLM2、度申相机；本流程暂不接 F4321。
- DMD → SLM1：等焦距、等倍率的倒像 4f 中继。
- SLM1 → SLM2、SLM2 → 相机：两段自由空间 ASM；中间有额外透镜时需要先扩展模型。
- ASM 复用主项目 `models/SLM/asm_propagation.py`；相位由 `torch.optim.SGD` 优化。
- 新建/恢复默认从硬件子项目自己的 `calibration_config.json` 读取参数，只使用标准库 json。GUI 不导入主项目 YAML、PyYAML、PyTorch 或 `models`。
- 默认采样 8 / 4.5 μm，P=2、K=1；标定基础网格仍为 704 / 1152，FFT 边长为网格边长乘 P×K。不同网格保留照明外围区域及层间物理坐标重采样，不强行改成训练模型的 640×640 画布。
- SLM1/SLM2 分别设置数值网格、采样间距和相位优化控制点；层间按坐标重采样复光场。
- 开发环境训练并导出标定包；GUI/EXE 可导入包完成相机反馈对准，运行时不依赖 PyTorch 或主项目 `models`。
- 每片 SLM 单独工作和双 SLM 联合工作各训练四个目标，共十二组。联合目标的两片相位一起优化。
- 原生 SLM 像素导出、灰度 LUT、8 位量化后重新传播验证；模拟预览、目标、相位数组同时保存。
- 实物流程自动采背景、测 DMD 坐标关系、补偿方向、使用导入的相位与预测参考、搜索 SLM 偏移/旋转/镜像、测局部偏移响应、独立图案及联合正反对照验证。开发环境也可选择测量后现场训练。
- 通过后应用参数；失败/取消尝试恢复原参数、原输入画面和相机曝光模式。恢复失败会明确报错。
- 原始相机帧直接从采集线程获取，不使用界面截图，不受预览刷新间隔和 CCD 预览旋转影响。

**这是已接入硬件接口的第一版软件自动对准，尚未在实际光路上验收。** 相机必须能观察到有效信号，参数需符合实际光路。程序不能自动移动没有电动控制的透镜/支架，也不会把不可观测或视野外区域标成已标定。

## 安装与启动

在 `tools` 目录执行：

```powershell
python -m pip install -r requirements-gui.txt
python .\apps\optical_control.py
```

上面是硬件 GUI / 打包环境，不安装 PyTorch。仅在**本地开发训练环境**额外执行 `python -m pip install -r calibration/requirements.txt`，并保留主项目 `models` 源码。训练时 CUDA 可用则自动用 GPU，否则用 CPU；GPU 构建需与本机驱动匹配。

## 从 UI 完成标定

1. 在第一页配置普通 DMD、两片 SLM、相机的设备编号和 SDK 路径，并同时启用四路硬件。
2. 相机选择 `bgr8` 或 `mono8`；首轮关闭 ROI，固定合理曝光/增益。自动白平衡、gamma 等图像处理应在相机配置中保持固定。
3. 点击第一页“自动标定…”或第二页“自动标定 / 光路对准”。
4. 点击“导入相位包…”，选择完整训练输出目录中的 `manifest.json`。程序检查 12 组相位、参考数组、尺寸、模拟分数和文件校验记录，载入并锁定训练参数；曝光稳定时间、平均帧数、搜索范围等仍可调整。顶部显示两片各自的导出尺寸、网格和采样。训练时的波长、传播距离和口径必须适合当前实物。
5. 填写可写的输出目录，点击“开始自动标定”。未连接时会生成全黑参考输入并按第一页配置连接；已连接时使用现有连接。无需提前手动加载相位或棋盘格。
6. 等待采集、搜索和验证。弹窗显示当前阶段；“停止”、主界面“停止全部”、断开和关闭窗口都会取消标定。底层 SDK 调用结束后释放资源。
7. 成功后，第二页的 DMD/SLM 方向和 SLM 偏移更新为结果，SLM2 外围灰度统一为标定使用的 0。原输入画面恢复，播放保持停止。结果目录同时保存可用“载入配置”读取的 `gui_configuration.json`。

相机 ROI、设备选择和图案操作在标定期间锁定。曝光关闭自动模式后由 SDK 确认；结束时恢复之前的曝光、增益和自动曝光设置。

开发环境可将“相位来源”切换为“本地训练（开发环境）”，填写两层参数后仅训练，或在采集 DMD 几何后现场训练并继续对准。**打包版隐藏训练按钮，只有导入模式，也拒绝通过内部接口启动训练。** demo 可检查界面及导入包，不能使用合成相机做真实标定。

### 离线训练与实际光路不一致时

导入模式使用固定的预测参考，不会为了适配当前采集画面自由平移或缩放参考。DMD 方向补偿后，程序将实际指令对应的白色口径与训练口径比较（数值网格上的差异最多 0.5%），并检查预测目标的相机覆盖率。

若旋转改变了口径，或目标超出相机视野，程序停止并恢复原设置，保存 `training_request.json`。把此参数文件带回开发环境重新训练，再导入新的完整训练目录：

```powershell
python .\calibration\train.py --config "本轮结果目录\training_request.json" --output .\output\calibration_retrained_01
```

此文件记录实测 DMD 方向和使目标居中的位置；波长、距离仍需正确。若使用自定义 LUT，重训环境也需可访问其原文件，或在参数里改为该环境的路径。视野太小、光路不符或模型误差仍可能要求实际调整，不能承诺仅换相位就解决所有情况。

## 独立训练

在本地开发环境安装训练依赖，生成并编辑参数文件：

```powershell
python -m pip install -r calibration/requirements.txt
python .\calibration\train.py --write-default-config .\calibration_config.json
python .\calibration\train.py --config .\calibration_config.json --output .\output\calibration_training_01
```

从项目根目录也可执行：

```powershell
python -m tools.calibration.train --config tools/calibration_config.json --output tools/output/calibration_training_01
```

输出目录必须不存在，避免覆盖已有训练结果。参数中 `device` 可设 `auto` / `cuda` / `cpu`。每片 SLM 可提供一个含 256 个 rad 值的文本 LUT（路径分别为 `slm1_lut`、`slm2_lut`）；未提供时采用显式记录的理想线性相位映射，默认灰度方向反向。LUT 路径相对于参数 JSON 文件解析。

`--write-default-config` 未指定 `--config` 时从子项目默认 JSON 生成快照。显式载入 JSON/标定包则始终使用保存值，旧文件缺少 P/K 时按原实现 P=2、K=1 解释；不会因为默认配置更新就改变旧参考图对应的光学参数。新包保存 `asm_padding_factor` / `asm_supersample_factor`，导入后锁定并校验。界面“恢复默认”重新读取子项目的 `calibration_config.json`，仅用于新训练，不读取主项目配置或 `SLM_OPTICS_CONFIG` 环境变量。

相机、搜索参数和逐器件 LUT 同样保存在子项目 JSON。标定 LUT 直接表示灰度 0～255 的器件实测相位；不会自动套用主项目导出参数，避免改变旧标定包的灰度物理含义。

默认训练三种组合各四个目标，共 12 组。把整个输出目录复制到设备电脑，在 GUI 中选择其中的 `manifest.json`。不要只复制 SLM PNG：相位图本身不包含自动对准所需的预测强度、坐标尺度和训练参数。普通相位图仍可通过主界面的 SLM 输入路径播放。

导入仅读取 JSON、8 位图像和无 pickle 的 NumPy 数组，不加载 PyTorch 权重，也不在设备端重新推理。标定包携带实际用到的 LUT 数组，导入时无需访问训练电脑的 LUT 路径。原始包不会改写，每轮会复制并检查一份副本留作记录。旧版公共网格训练包需要用新版重新生成。

## 输出结构

```text
output/calibration/
  last_config.json
  references_<id>/                # 未连接时使用的全黑参考图
  <时间>_<id>/
    config.json                   # 本次初始参数
    training_request.json         # 测出 DMD 方向/相机位置后的重训参数
    dmd/                          # 单点、白图、黑图
    slm1/flat.png
    slm2/flat.png
    training/                     # 导入包的副本，或开发环境现场训练结果
      manifest.json               # 状态、网格、路径、模拟分数、SHA-256 文件校验
      config.json                 # 训练时实际使用的参数
      slm1_lut_rad.npy
      slm2_lut_rad.npy
      slm1|slm2|joint/
        dots|arrow|corners|holdout/
          slm1.png / slm2.png      # 实际可加载的原生 8 位相位图
          *_phase_rad.npy
          expected.npy            # 灰度量化后预测强度
          target.npy
          target.png
          simulation.png
    captures/<批次>/
      00.png ...                  # 未经软件旋转的原始相机帧
      capture.json                # 帧号、设备信息、图案及控制参数
      overlay.png                 # 绿：采集；红：预测。仅显示时归一化
    report.json                   # 所有阶段分数、状态或失败原因
    calibration.json              # 完成验证的结果及是否成功应用
    gui_configuration.json        # 应用成功后可载入的主界面配置
    task_status.json              # 任务异常时的补充信息
```

`passed` 只表示本轮有效视野、配置和验证图案通过阈值，绝非整个光路机械位置的绝对真值。`not_applied` 表示验证后应用/恢复过程失败或取消，不能当作已应用。未完成的训练 manifest 不标记 `trained`。

## 网格与质量参数

### 三种尺寸分别设置

下面是默认 DMD 640 × 640、5.4 μm、口径 3.456 mm 时的参数：

| 参数 | SLM1 | SLM2 | 用途 |
|---|---|---|---|
| 器件物理像素间距 | 8 μm | 4.5 μm | 口径与硬件像素换算 |
| 导出相位图有效尺寸 | 432 × 432 | 768 × 768 | 实际发送的原生像素，按 DMD 有效口径计算 |
| ASM 数值采样间距 | 8 μm | 4.5 μm | 默认等于对应器件的物理像素间距，可手动调整 |
| ASM 网格边长 | 704 | 1152 | 包含外围计算区域，可分别调整 |
| ASM 计算视野 | 5.632 mm | 5.184 mm | 网格边长 × 采样间距 |
| 相位优化控制点边长 | 128 | 128 | 两片分别优化，插值至各自导出尺寸 |

物理像素间距与 `models/SLM/physical_defaults.py` 中的器件参数保持一致，由开发测试核对；硬件 GUI 不导入该模型包。标定模块的 ASM 默认采样按硬件设为 **8 μm、4.5 μm**，本地训练可手动改动，不会在每次开始时覆盖手动值。主项目的经验采样 **13 μm、6.4 μm** 保留在主项目中。SLM2 的导出有效区按相同设计口径选取；自由传播不保证光束恰好填满此区域。

主项目当前两个 ASM 数组均为 640 × 640，使用不同数值采样。432/768 是原生导出尺寸。标定模块按硬件像素间距采样，并保留至少 1.5 倍有效口径的计算视野；按 64 点步长扩展后，初始边长为 704/1152，SLM1 的视野覆盖 SLM2。网格包含外围计算区域，因此不直接等于相位图尺寸，也不是整块 1920×1080 面板的尺寸。默认范围检查不能代替采样精度和收敛验证。

配置字段分别为 `slm1_grid_size` / `slm2_grid_size`、`slm1_sampling_um` / `slm2_sampling_um`、`slm1_phase_resolution` / `slm2_phase_resolution`。改变 ASM 网格不改变相位图导出尺寸；改变 DMD 有效口径或器件物理像素间距会改变导出尺寸。

### 界面的网格自动调整

选择“本地训练（开发环境）”后，修改 DMD 有效尺寸、DMD 物理像素间距、任一层 ASM 网格或数值采样间距，会自动检查计算范围。键盘输入在按回车或离开输入框后生效：

- 先让 SLM2 计算视野覆盖有效口径的至少 1.5 倍，再让 SLM1 同时覆盖此口径和 SLM2 计算视野。
- 仅扩大不足的网格，自动扩大的边长向上取到 64 的倍数；已足够大的手动值会保留，不要求是 64 的倍数，也不会自动缩小。
- 例如默认 SLM1 采样从 8 改为 7 μm 时，SLM1 网格从 704 自动增到 768。手动增大 SLM2 时，如果超出 SLM1 范围，SLM1 也会随之增大。载入旧版 512/1024、13/6.4 μm 参数时仍保留原值。
- 调整结果会显示在输入框、尺寸摘要和日志中，训练及保存配置都使用调整后的值。开发模式载入范围不足的参数文件时也会自动调整。
- 当前边长上限为 4096；若仍不能覆盖，会提示所需边长，需调整采样间距或计算范围。更大网格会增加计算量和内存/显存占用；范围检查通过不代表数值精度已经充分。

导入相位包时保留训练时的精确网格与采样参数，不做自动调整。修改这些参数需要在开发环境重新训练。

### 将相位控制点设置为 640 × 640

两个“相位优化控制点边长”均可填 `640`，允许范围为 8～1920。此时每片 SLM 有 409600 个待优化参数，是 128 × 128 的 25 倍；总训练耗时还取决于 ASM 网格和步数。

控制点在传播前会重采样到硬件有效区：默认口径下，SLM1 为 **640 × 640 → 432 × 432**，SLM2 为 **640 × 640 → 768 × 768**。界面摘要会显示这个对应关系。增加控制点不会自动增大硬件有效区；SLM1 超出原生分辨率的控制点会被缩小，不保证得到更多可用细节。最终效果仍需检查数值采样、训练收敛及实物结果。

### 跨网格传播与坐标

流程为：SLM1 网格调制 → 按 SLM1 采样传播至 SLM2 平面 → 将复光场的实部/虚部重采样到 SLM2 坐标 → SLM2 调制 → 按 SLM2 采样传播至相机。重采样保留两网格的中心和坐标单位；向更粗采样转换时先去除高于目标 Nyquist 频率的分量。不会将强度图直接缩放后当作复光场。

这一层间操作是双线性复光场插值的近似，**不是严格的缩放角谱传播算法**。目标强度、量化后预测强度及相机映射统一使用最后的 SLM2 网格。SLM1 传播后的计算视野必须覆盖 SLM2 网格，两层还需各覆盖有效口径的至少 1.5 倍；这是初始检查，不替代数值收敛验证。

更高精度时，应减小各层采样间距并相应增加网格，保持计算视野，再比较预测强度、匹配分数及硬件结果。原生像素导出不意味着粗网格能解析全部器件高频细节。减小经验采样也会改变当前模型行为，不能仅凭训练损失判断实物正确性。

载入旧版 `grid_size` / `sampling_um` / `phase_resolution` 配置时，会把原值分别填入两片 SLM 并显示迁移提示；开发模式随后仅对范围不足的网格执行上述自动调整并记录日志。点击“恢复默认”可使用本版分层默认值；这会恢复全部标定参数，请重新核对波长、距离等设置。旧输出文件保留；**修改传播参数后需重新训练**，不能把旧相位图视为新参数下的结果。

### 训练与采集质量

- 默认为每组 400 步 SGD，两片各使用 128 × 128 控制点，允许分别调整。SGD 使用归一化梯度控制步长；不需要标注数据集。
- 默认每次等待 0.5 s，丢弃 3 帧，再平均 5 帧。软件时序不保证厂商内部深缓冲已完全清空；实机应验证并增大等待/丢帧数。高曝光时还需增加采集超时。
- 默认搜索镜像及 30° 间隔方向，再在当前最优方向附近细调；偏移限制在初值 ±32 个面板像素。超出面板的候选不发送。若完整旋转的有效图无法放进面板，需要减小有效区，不能偷偷裁切。
- 相机目标有效覆盖率默认至少 85%，几何独立验证 RMS 默认不超过 2 px，强度匹配阈值默认 0.65，均为可调整的初始工程阈值。

## 打包（在 tools 目录）

使用只安装 `requirements-gui.txt` 的干净环境，沿用现有的 `Qing.spec`。其中已排除训练模块和 PyTorch，并配置界面、`QIC.ico`、`Qing.exe` 名称和 `lib` 依赖目录。准备打包时执行：

```powershell
python -m PyInstaller --clean --noconfirm .\Qing.spec
```

发布整个 `dist/Qing` 文件夹，标定训练包另外携带并导入。厂商 SDK 仍按现有方式外置或自行收集；目标电脑需要驱动及运行库。外置输出目录设为可写绝对路径。已在禁止导入 `torch` 和 `models` 的隔离进程检查 GUI 导入及模拟标定流程；本次未构建 EXE，未做实物验收。
